docs/journal/JOURNAL.md 전체를 읽고 개발 경험을 회고하여 docs/journal/LESSONS.md 를 업데이트한다.

## 사용법
```
/retrospect              ← 전체 회고
/retrospect phase 3      ← Phase 3까지만 회고
/retrospect agents       ← 에이전트 효과성 집중 분석
```

## 실행 절차

1. **데이터 수집**
   - docs/journal/JOURNAL.md 전체 읽기
   - docs/journal/phases/ 내 모든 파일 읽기 (존재 시)
   - docs/AGENTS.md 읽어 계획 vs 실제 비교

2. **패턴 분석** — 다음을 추출한다:
   - `**바이브**: 😤막힘` 항목 → 반복된 고통 포인트
   - `**바이브**: 🎉완성` 항목 → 성공 패턴
   - `**결정**:` 항목 → 주요 기술 결정 목록
   - `**교훈**:` 항목 → 원시 교훈 목록

3. **LESSONS.md 업데이트** — 분석 결과를 다음 구조로 작성:

   ```markdown
   # Lessons Learned — SQLD 바이브 코딩

   > 업데이트: [현재 날짜] | 저널 항목 수: N개 | 총 Phase: N

   ## 잘 된 것 (Keep)
   <!-- 반복하고 싶은 패턴 -->

   ## 개선할 것 (Improve)
   <!-- 방향은 맞지만 실행이 아쉬웠던 것 -->

   ## 다음엔 하지 말 것 (Stop)
   <!-- 시간 낭비 또는 역효과였던 것 -->

   ## 다음엔 꼭 할 것 (Start)
   <!-- 이번엔 없었지만 했어야 할 것 -->

   ## 에이전트별 평가
   | 에이전트 | 효과성 | 주요 성과 | 개선점 |

   ## AI 협업 인사이트
   <!-- Claude가 잘한 것 / 인간 개입이 필요했던 것 -->

   ## 기술 스택 평가
   <!-- Next.js/Tailwind/JSON 선택이 실제로 좋았나 -->

   ## 바이브 코딩 vs 전통 개발 비교
   <!-- 속도, 품질, 경험 측면 -->

   ## 핵심 교훈 TOP 5
   <!-- 가장 중요한 인사이트 5개 -->
   ```

4. 완료 후 "회고 완료 ✓ — N개 교훈 도출" 메시지 출력.
