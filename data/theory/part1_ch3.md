# 1과목 3장: 전사아키텍처 관리 및 활용

## 1. 전사아키텍처 관리 체계

EA 관리 체계는 수립된 아키텍처를 지속적으로 유지·통제하는 거버넌스 구조이다.

### 1.1 EA 거버넌스 4대 구성 요소

| 구성 요소 | 설명 |
|---------|------|
| 조직(Organization) | EA를 관리할 위원회와 전담팀(공식 의사결정 기구) |
| 역할과 책임(RACI) | 각 조직·구성원의 권한과 책임을 명확히 함 |
| 프로세스(Process) | EA 활동을 수행할 표준·반복 가능한 운영 절차 |
| 인력 역량(People) | 담당 아키텍트의 전문 역량 지속 강화 |

### 1.2 EA 관리 조직 4계층과 핵심 역할 5종

**조직 4계층**

| 계층 | 조직명 | 구성 | 주요 역할(RACI) |
|---|---|---|---|
| 위원회 | EA 운영위원회(Steering Committee) | 위원장 CIO, 주요 부서장 | 비전·정책 승인(**A**), 대규모 투자 의사결정 |
| 전담 조직 | EA팀(EA Office) | EA/DA 총괄 | 프레임워크·표준 개발·관리(**R**), 변경관리 운영 |
| 실무 그룹 | 도메인별 아키텍트 그룹(BA/DA/AA/TA/SA) | 도메인 전문가(모델러·DBA 등) | 도메인별 모델링·표준 적용(**R**) |
| 참여자 | 현업 부서·IT 개발/운영팀 | 모든 임직원 | 표준 준수, 요구사항 제기(**C, I**) |

**핵심 역할 5종**

| 역할 | 주요 내용 | RACI |
|---|---|---|
| CIO/EA 담당임원 | 비전·방향성 제시, 정책 승인, 이슈 조정 | **A** |
| EDA/EA 전담조직 | 정책·표준 초안, 변경관리 운영, 통합모델 개발 | 총괄 |
| DA(데이터 아키텍트) | 전사 데이터 표준 개발·관리, 표준 준수 검토 | **R** |
| 모델러/DBA | 도메인 모델링, 물리 DB 설계·운영 | — |
| 사용자(User) | 업무 활용, 품질 문제 제기, 신규 요구 제기 | **C, I** |

**변경관리 RACI 매트릭스(예)**: 변경 요구 접수/영향분석/표준변경안 수립 = DA·EA팀 R, 변경안 검토·승인 = CIO/EDA A, 모든 활동에서 사용자는 C/I. 모든 활동에 A와 R은 단 하나씩만 지정되어야 한다.

### 1.3 6대 관리 프로세스 (연간 선순환)

| 시기 | 프로세스 | 내용 |
|---|---|---|
| 연초 | ① 기획 | 방향 재점검, 연간 운영계획·KPI 수립 |
| 연중 | ② 변경관리 | 통제된 절차로 아키텍처 갱신(검토·승인·이행·교육·평가) |
| 연중 | ③ 준수통제 | 표준 준수 정기 점검, 예외 심의·관리 |
| 연중 | ④ 활용지원 | 표준 공지·교육, 활용 사례 발굴·전파 |
| 연중 | ⑤ 시스템 운영 | 레포·포털 권한관리, 백업·복구, 보안점검 |
| 연말 | ⑥ 평가 | KPI 달성도·성숙도 진단 → 차기 기획에 환류 |

> 중앙의 EA 레포지터리·포털이 6개 프로세스를 관통하는 정보 허브 역할을 한다.

### 1.4 아키텍처 준수 관리

| 단계 | 내용 |
|------|------|
| 기준 수립 | 아키텍처 원칙·표준·지침 정의 |
| 프로젝트 검토 | ARB의 아키텍처 준수 검토 |
| 편차 관리 | 불가피한 편차 공식 승인 |
| 사후 감사 | 구현 결과의 EA 준수 여부 확인 |

**아키텍처 편차(Deviation):**

| 유형 | 설명 |
|------|------|
| 임시 편차(Temporary) | 특정 기간 동안만 허용 |
| 영구 편차(Permanent) | 지속적으로 허용 |

## 2. 전사아키텍처 관리 시스템 (EAMS)

EA 관리 시스템(EAMS, Enterprise Architecture Management System)은 EA 정보의 단일 진실 공급원(SSoT)이자 거버넌스 프로세스를 자동화하는 통합 플랫폼이다.

### 2.1 EAMS 4대 구성요소

| 구성요소 | 핵심 동사 | 설명 |
|---|---|---|
| 모델링 도구 | 만든다 | ArchiMate·UML·BPMN 등 EA 도구, ERD 작성 데이터 모델링 도구 — 레포지터리와 실시간 연동 |
| 레포지터리 | 저장·연결한다 | 모든 아키텍처 정보를 메타모델에 따라 구조화 저장하는 중앙 DB. 버전 통제·접근 제어 |
| 포털 | 찾아보고 활용한다 | 웹 기반으로 레포지터리 정보에 접근하는 인터페이스. 검색·조회·시각화 |
| 분석·의사결정 지원 도구 | 수행한다 | 영향 분석, 현행-목표 비교 분석, 포트폴리오 분석, 시나리오 시뮬레이션 |

**TOGAF 리포지터리 4대 구성 요소** (참고): 아키텍처 메타모델, 아키텍처 역량, 아키텍처 랜드스케이프, 표준 정보 기반

### 2.2 EAMS 핵심 기능 8가지

| # | 기능 | 설명 |
|---|---|---|
| ① | 버전·형상 관리 | 변경 이력 추적, 베이스라인 저장·비교 |
| ② | 역할 기반 접근제어 | 역할별 조회·수정·삭제 권한 세밀 제어(RBAC) |
| ③ | 활용 통계·대시보드 | 자주 활용되는 정보와 참여 사용자 통계 |
| ④ | 현행-목표 비교 분석 | As-Is/To-Be 시각적 비교로 Gap·이행과제 도출 지원 |
| ⑤ | 참조모델 연계 | BRM·DRM·TRM 매핑으로 일관성 검증 |
| ⑥ | 사용자 맞춤형 뷰 | 경영진·현업·개발자 관심사에 맞춘 대시보드 |
| ⑦ | 영향 분석 | 변경 파급효과 자동 추적·시각화 |
| ⑧ | 개방형 API | CMDB·PPM·ITSM 등과 연동 |

> 4가지 핵심 행위로 재분류: **지킨다**(①②) · **비교한다**(④⑦) · **보여준다**(③⑤⑥) · **연결한다**(⑧)

### 2.3 EA 성과 관리 지표 (4관점)

| 관점 | 세부 지표 |
|---|---|
| 효율성 | 표준 준수율, 재사용률, 변경처리 리드타임 |
| 품질 | 모델 최신성, 데이터 품질지표 충족률 |
| 활용도 | 포털 MAU·페이지뷰, 의사결정 지원 만족도 |
| 비즈니스 가치 | IT 비용 절감액, 신규 서비스 출시기간 단축률(TTM) |

> **핵심**: 과거의 "EA수립/활용/준수/IT투자효과" 4개 카테고리는 위 4관점(효율성·품질·활용도·비즈니스가치)으로 재분류된다.

## 3. 전사아키텍처 활용

EA 활용은 수립된 아키텍처를 실제 IT 의사결정과 업무에 적극적으로 사용하는 것이다. 성숙도 5단계 중 최적화(Optimizing)가 최고 수준이다.

### 3.0 활용① 목표 아키텍처 이행 지원 (대규모 프로젝트)

| 단계 | 내용 |
|---|---|
| 요구사항 분석 | 전사 BA·목표 부합 여부 검토 |
| 설계 | DA·AA·TA·SA 원칙·표준 준수 검토(설계 검토) |
| 테스트 및 이행 | 구현 검증, 타 시스템 영향 분석 |
| 프로젝트 관리 게이트 | 착수·분석·설계·종료 단계 Go/No-Go 시 EA 준수 검토 |

### 3.0a 활용② 상시 IT업무 지원

표준 확산(TRM·DRM·표준API 재사용) · 품질·보안 내재화(사전 영향 분석) · 데이터 거버넌스 실행 · IT 투자·성과 관리(중복 검토, 포트폴리오 평가)

### 3.0b 활용 시나리오 5종

| 시나리오 | 담당자 | 활용 EA 정보 | 기대 효과 |
|---|---|---|---|
| 신규 사업 기획 | IT 기획자 | BA, 애플리케이션 포트폴리오 | 전략적 정렬, 중복투자 방지 |
| 시스템 설계 검토 | 아키텍트 | 목표 아키텍처, TRM, DRM | 설계 품질 향상 |
| 정보보호 승인 | 보안 담당자 | SA, 데이터 등급 | 보안 규제 준수 |
| 데이터 표준 적용 | 모델러·개발자 | DRM, 표준 용어사전 | 데이터 일관성 확보 |
| 데이터 품질 개선 | 데이터 관리자 | 데이터 흐름도·모델, 품질 측정 결과 | 신뢰성 있는 의사결정 |

### 3.0c PDCA 환류체계 5단계

평가 및 분석 → 개선 계획 수립 → 정책·표준·모델 갱신 → 교육 및 공지 → 재평가

### 3.1 IT 투자 의사결정 지원

| 활용 방법 | 내용 |
|---------|------|
| 신규 투자 타당성 검토 | EA 기반으로 신규 시스템 필요성·중복성 판단 |
| 아키텍처 적합성 평가 | 프로젝트가 EA 방향과 부합하는지 평가 |
| 기술 표준 적용 | 표준화된 기술 컴포넌트 우선 사용 유도 |

### 3.2 프로젝트 관리 지원

- **범위 정의**: EA 기반으로 프로젝트 영향 범위 파악
- **설계 기준**: 아키텍처 원칙·표준을 설계 기준으로 적용
- **ARB 검토**: 프로젝트 아키텍처의 EA 준수 여부 검토

### 3.3 정보화 전략 계획(ISP) 연계

| EA 산출물 | ISP 활용 |
|---------|---------|
| AS-IS 아키텍처 | 현황 분석 기반 자료 |
| TO-BE 아키텍처 | 미래 정보화 방향 |
| 이행 계획 | ISP 로드맵 수립 기준 |

### 3.4 EA 활용 수준과 성숙도 (5단계 기준)

| 성숙도 단계 | 활용 수준 |
|--------|---------|
| 3단계(정의) | 표준·프로세스 문서화, 거버넌스 수립 완료 — 활용은 아직 미흡 |
| 4단계(관리) | KPI로 정량 측정·관리, 성과 기반 개선 |
| 5단계(최적화, Optimizing) | EA를 의사결정에 적극 활용, 조직문화로 내재화 (최고 수준) |

### 3.5 EA 지식 관리

| 방법 | 내용 |
|------|------|
| 아키텍처 패턴 라이브러리 | 검증된 설계 패턴 축적·공유 |
| 사례(Case Study) 관리 | 성공/실패 사례 기록 |
| 역량 개발 교육 | 아키텍트 역량 향상 프로그램 |

## 4. 데이터 거버넌스

### 4.1 데이터 거버넌스 등장 배경

데이터량의 급증과 함께 "항상 이용 가능한 데이터의 시대"에 접어들면서, 데이터가 기업의 귀중한 자산으로 인식되었다. 높은 품질의 데이터를 유지·관리하기 위한 체계의 필요성으로 등장했다.

### 4.2 데이터 거버넌스 정의와 핵심 관점

**정의**: "기업이나 조직의 목적에 맞게 높은 품질의 데이터를 사용할 수 있도록 정의한 체계"

| 핵심 관점 | 설명 |
|---------|------|
| 책임(Accountability) | 조직의 모든 계층에서 데이터 책임 정의 |
| 일관성(Consistency) | 표준화된 절차를 통한 데이터 일관성 유지 |
| 적응성(Adaptability) | 조직의 전략적 방향에 맞는 적응 |

### 4.3 데이터 거버넌스 필수 요소

1. 데이터 요소에 대한 표준화된 명칭 및 생성 규칙
2. DB 시스템에서의 업무 데이터 물리적 위치 정의
3. 조직에 맞는 데이터 품질 규칙
4. 데이터 사용 규칙
5. 데이터 통제자·관리자·소유자의 적절한 통제

> **핵심**: 데이터 거버넌스는 IT 관련 조직만이 아닌 **전사적인 노력**이 필요하다.

### 4.4 데이터 거버넌스 역할 정의

| 역할 | 설명 |
|------|------|
| **데이터 통제자(Data Controller)** | 전사적 데이터 거버넌스 운영 총괄 |
| **데이터 관리자(Data Administrator)** | 데이터 품질 및 무결성 책임 |
| **데이터 소유자(Data Owner)** | 특정 데이터 도메인의 접근 권한 및 품질 책임 |

### 4.5 데이터 거버넌스 주요 고려사항

| 고려사항 | 내용 |
|---------|------|
| 보안성 | 역할별 접근 권한 부여 및 민감 데이터 보호 |
| 무결성 | 데이터 처리 원칙 정의 및 모니터링 |
| 데이터 품질 | 최신 상태를 정확히 반영하는 관리 체계 |
| 오너십(Ownership) | 소유권 부여로 책임 확보 |

### 4.6 데이터 아키텍트(DA)의 역량

| 역량 유형 | 설명 |
|---------|------|
| **리더십 역량** | 전사적 공감대 형성 및 변화 관리 |
| **기술적 역량** | 이론과 실제 구축 능력 (모델링·표준화·DB 지식) |
| **활용 역량** | 데이터 품질 유지로 업무 효과성 향상 |

### 4.7 현대적 거버넌스 체계 수립 고려사항

1. **전사 범위 정의**: 내부 및 외부 데이터 원천 포함
2. **민감 데이터 처리**: 개인정보 외 유출 방지 대상 식별
3. **새로운 품질 관리**: 빅데이터에 적합한 검증 방식 적용
4. **카탈로그/메타데이터 관리**: 데이터 위치 및 정보 체계화
5. **적재 및 용량 관리**: 지속적 점검 및 예측

1. ARB: 프로젝트 아키텍처 준수 여부 검토 기구
2. EA 거버넌스 4대 구성 요소: 조직(Organization)·역할과 책임(RACI)·프로세스(Process)·인력 역량(People)
3. EA 관리조직 4계층: 운영위원회(A)-EA팀(R)-도메인아키텍트그룹(R)-참여자(C/I)
4. 핵심 역할 5종: CIO/EA담당임원(A), EDA/EA전담조직, DA(R), 모델러/DBA, 사용자(C/I)
5. 6대 관리 프로세스(연간 선순환): 기획(연초)→변경관리·준수통제·활용지원·시스템운영(연중)→평가(연말)
6. EAMS 4대 구성요소: 모델링도구(만든다)·레포지터리(저장연결한다)·포털(찾아보고 활용한다)·분석/의사결정지원도구(수행한다)
7. EAMS 핵심기능 8가지: 버전형상관리·역할기반접근제어·활용통계대시보드·현행목표비교분석·참조모델연계·사용자맞춤형뷰·영향분석·개방형API
8. TOGAF 리포지터리 구성(참고): 메타모델·역량·랜드스케이프·표준 정보 기반
9. 아키텍처 편차: 표준 불준수 시 공식 승인 예외 (임시 편차 / 영구 편차)
10. EA 성과 지표 4관점: 효율성·품질·활용도·비즈니스가치 (기존 EA수립/활용/준수/IT투자효과 분류를 재분류)
11. 성숙도 5단계, 최고 = 최적화(Optimizing) — part1_ch1과 통일
12. 활용① 목표아키텍처 이행지원 4단계: 요구사항분석·설계·테스트및이행·프로젝트관리게이트
13. 활용② 상시 IT업무 지원: 표준확산·품질보안내재화·데이터거버넌스실행·IT투자성과관리
14. 활용 시나리오 5종: 신규사업기획·시스템설계검토·정보보호승인·데이터표준적용·데이터품질개선
15. PDCA 환류체계 5단계: 평가및분석→개선계획수립→정책표준모델갱신→교육및공지→재평가
16. EA와 ISP 연계: AS-IS→현황, TO-BE→미래방향, 이행계획→로드맵
17. 아키텍처 패턴 라이브러리: 검증된 설계 패턴 재사용 촉진
18. 데이터 거버넌스(4절)는 별도 보완 내용으로 유지 — 통제자/관리자/소유자 역할 구분 등
